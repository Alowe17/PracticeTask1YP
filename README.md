Проект нужно делать индивидуально <br></strong></h3>

<h4>Базовые требования к выполнению </h4><br>
1. <strong>Модульность</strong> - код должен быть разделён на логические компоненты (сервисы, модели, интерфейсы, утилиты и т.п.). <br>
2. <strong>Использование принципов ООП</strong> (инкапсуляция, наследование, полиморфизм). <br>
3. <strong>Логирование и обработка ошибок</strong> - обязательное использование системы логов и корректная обработка исключений. <br>
4. <strong>Документирование</strong> - наличие комментариев и краткого описания модуля, его интерфейсов и классов. <br>
5. <strong>Возможность тестирования</strong> - модуль должен быть протестирован отдельно (например, через unit-тесты или демонстрационный класс). <br>
<br>

<h4>Предложенные темы модулей </h4>
Студент должен реализовать полноценный backend-модуль на Spring с подключением к базе данных (например, PostgreSQL, MySQL) и системой безопасности Spring Security.<br>
В таком случае:
- проект должен иметь REST API с чёткой структурой контроллеров, сервисов и репозиториев; <br>
- реализованы базовые CRUD-операции; <br>
- предусмотрена аутентификация и авторизация пользователей (JWT, Basic Auth или сессии); <br>
- используются аннотации @RestController, @Service, @Repository, @Entity; <br>
- настроено подключение к базе; <br>
- Swagger для документирования API. <br>
- Выполнен пользовательский интерфейс с комфортной навигацией и UX-ориентированным дизайном. <br>

<h4>Результат выполнения</h4>
Каждый студент должен представить: <br>
- Исходный код модуля. <br>
- Отчет. <br>
- Демонстрацию работы (консольный пример, REST-запрос или интерфейс). <br>
- При наличии - интеграцию модуля в другое приложение или объяснение, как этот модуль можно интегрировать в другое приложение. <br>
